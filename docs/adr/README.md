# Architecture Decision Records

Журнал архитектурных решений проекта. Правила ведения:

- Один файл — одно решение: `NNNN-краткое-название.md`, номер по возрастанию, без пропусков.
- **ADR неизменяемы после принятия.** Если решение пересматривается, создаётся новый ADR, который явно ссылается на предыдущий и помечает его как `Superseded by ADR-000X` (в самом старом файле статус меняется одной строкой, тело — нет).
- Заголовок каждого ADR: `Статус` (`Proposed` / `Accepted` / `Superseded by ADR-000X`), `Дата`, далее содержание решения.
- ADR заводится не для рутинных решений (тех фиксирует `docs/phases/phase-N-implementation.md`), а для решений, которые отклоняются от [ADR-0001](0001-baseline-architecture.md) или существенно уточняют недоопределённые в нём места (например, если Phase 0-спайк опроверг предположение из ADR-0001 и потребовал другой архитектурный путь).
