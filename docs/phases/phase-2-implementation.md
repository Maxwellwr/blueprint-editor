# Phase 2 — Add/remove/rotate entities + entity_number/wire bookkeeping — реализация

- Ветка: `phase-2-mutate` → `main`
- Версия после мержа: `info.json` `0.3.0`
- Дата завершения: 2026-09-06

## Что сделано

- `scripts/state.lua` — `Session.selected_palette_item` (новое аддитивное поле, runtime-состояние ad-hoc палитры, не часть импортированных данных).
- `scripts/migrations.lua` — шаг `0.3.0`: backfill `EntityRecord.wires = entity.wires or {}` для сессий, переживших Phase 1.
- `scripts/blueprint_io.lua` — `build_import_data` расширена: строит `EntityRecord.wires` из `BlueprintEntity.wires` при импорте, по `internal_id`, а не по `entity_number` (ADR-0001 §6). Дедупликация двунаправленная и устойчивая к обоим возможным форматам сырых данных (см. «Найденные факты» ниже). Также: `blueprint_center` теперь округляется до целого при построении `import_data` (найдено playtest'ом, см. «Решения по ходу»).
- `scripts/canvas.lua` (новый) — мутационное API: `place_entity`, `remove_entity`, `rotate_entity`, `find_entity_at`, плюс чистая логика с TDD-покрытием: `snap_position` (реплицирует правило центрирования Factorio — нечётный размер на центр тайла, чётный на границу), `next_direction` (шаг в четверть оборота, корректный wraparound в обе стороны), `remove_wire_references` (флагманский пример TDD из `docs/sdlc.md`), `to_local_position` (обратная операция офсета рендера — стала публичной в ходе фазы, см. ниже).
- `scripts/rendering.lua` — `draw_entity`/`clear_entity_render` (поштучные аналоги `draw_entities`/`clear_session_renders`, без полной перерисовки сессии на каждое действие).
- `scripts/input.lua` (новый) — обработчики `on_player_selected_area`/`on_player_alt_selected_area`/`on_player_reverse_selected_area` (все три ведут в общую логику размещения/удаления), `eb-rotate`/`eb-delete`/`eb-pick-entity`/`eb-cycle-palette-next`/`eb-cycle-palette-prev`, `on_player_cursor_stack_changed` (переэкипировка инструмента). Ad-hoc `PALETTE_ITEMS` — 7 жёстко зашитых типов, отфильтрованных по фактическому наличию прототипа при циклировании.
- `scripts/surface.lua` — `teleport_in` экипирует `eb-cursor-tool` в обоих режимах (не только "new", как в Phase 1).
- `scripts/debug.lua` (новый) — команда `eb-dump-session`, дампит `session.entities`/`session.tiles` раздельно (не всю `Session` — там же `LuaObject`-поля, нечитаемые через `serpent.block`).
- `data/custom-input.lua` — 5 новых custom-input: `eb-rotate` (R), `eb-delete` (DELETE), `eb-pick-entity` (Q), `eb-cycle-palette-next`/`eb-cycle-palette-prev` (`RIGHTBRACKET`/`LEFTBRACKET`), плюс `reverse_select` на самом `eb-cursor-tool` (правый клик как альтернатива Shift+левый клик для удаления).
- `data/selection-tool.lua` — иконка `eb-cursor-tool` заменена с `blueprint.png` на `copy-paste-tool.png` (см. «Решения по ходу»).
- `control.lua` — подключены `input.lua`/`debug.lua`, зарегистрированы все новые события/custom-input/команда; удалён спайковый `on_selected_area` из Phase 0.
- `spec/canvas_spec.lua` (новый), `spec/blueprint_io_spec.lua` (расширен) — `busted`, 25/25 тестов.

## Найденные API-факты (расхождения с ADR-0001 §6, подтверждены)

1. **`BlueprintWire` — позиционный кортеж, не именованная таблица.** `{source_entity_number, source_wire_connector_id, target_entity_number, target_wire_connector_id}`, а не `{wire_type=, this_conn=, target_conn=}`, как предполагал псевдокод ADR. Подтверждено `lua-api.factorio.com/2.0.77` до написания кода.
2. **Раздельно проверено и позже подтверждено playtest'ом: Factorio дублирует каждый провод в `wires` ОБЕИХ связанных сущностей**, не только одной стороны. На реальном экспорте трёх столбов: у столба 1 `raw.wires = {{1,5,2,5}}`, у столба 2 (среднего) — независимо `{{2,5,1,5}, {2,5,3,5}}` (тот же провод к столбу 1, с обратным порядком source/target, плюс свой к столбу 3). Импорт (`build_import_data`) был написан устойчивым к обоим возможным исходам заранее — находка подтвердила, что дедупликация была не подстраховкой, а необходимостью.
3. **Валидные имена клавиш для `key_sequence`** — из `LEFTBRACKET`/`RIGHTBRACKET` (капсом, без дефиса и пробела), не `bracketleft`/`bracketright`. Список подтверждён по `doc-html/prototype-api.json` установленной копии игры. Factorio не падает на невалидном имени при загрузке data-стадии — молча оставляет биндинг неназначенным, без единой строки в логе (см. «Решения по ходу», найдено вторым раундом playtest'а).
4. **`LuaEntityPrototype.supports_direction`** (bool) — использован в `rotate_entity`, чтобы не пытаться вращать сущности, которые в принципе не вращаются (не было в ADR).

## Решения, принятые по ходу (отклонения/дополнения к phase-2-plan.md)

Порядок находок отражает реальную последовательность: SDD-исполнение по задачам плана → финальный whole-branch review (до playtest) → первый раунд ручного playtest'а (3 бага) → второй раунд (1 баг: клавиши) → verification по логу (DoD-тест провода подтверждён) → второй раунд `/code-review` на итоговом диффе (6 находок).

1. **Финальный ревью нашёл и потребовал исправить до playtest'а: `place_entity` писал мировые координаты клика в `raw.position`, который весь остальной код (рендер, `find_entity_at`) трактует как локальные координаты blueprint'а.** Реальный баг дизайна самого плана (Задача 3/7), а не отклонение исполнителя от плана. Разместить что-либо было бы физически невозможно (спрайт уезжал на величину `canvas_offset`, ~1024 тайла). Исправлено: `to_local_position` стала публичной (`canvas.to_local_position`), `place_entity` конвертирует входящую позицию перед снапом. Добавлены TDD-тесты на `to_local_position` (`assert.near`, не `assert.are.same` — IEEE-754 double не даёт точного представления тестовых фикстур типа `1026.3`).
2. **Тот же ревью: жёстко зашитая палитра могла упасть с крашем на моде без одного из 7 базовых прототипов.** Добавлена фильтрация `is_placeable` при циклировании палитры — пропускает недоступные имена, сообщает игроку, если не осталось ни одного.
3. **Первый раунд ручного playtest'а нашёл 3 независимых бага** (не покрытых ни TDD, ни финальным ревью — все API-зависимые, видны только в реальной игре):
   - **Сетка не совпадала с раскладкой сущностей.** `blueprint_center` (bounding-box middle, почти никогда не целый) использовался как офсет рендера без округления, а `draw_grid` рисует линии по целым координатам — сущности систематически смещались на дробную величину и попадали на пересечения линий, а не в клетки. Исправлено округлением `blueprint_center` до целого в точке использования (`import_from_stack`); `compute_bounding_box_center` и её тесты не тронуты.
   - **Иконка `eb-cursor-tool` была `blueprint.png`** (выбрано в Phase 0, до появления необходимости отличать инструмент от настоящего чертежа) — игрок не мог понять, что у него в руке. Заменена на `copy-paste-tool.png` (проверено по файлам установленной игры — тот же 120×64 mip-набор, `icon_size = 64` не меняется).
   - **Правый клик не удалял.** У tool'а был определён только `alt_select` (Shift+левый клик); обычное правое нажатие — отдельный режим `reverse_select`, которого в прототипе не было вовсе, поэтому Factorio ничего не делала. Добавлен `reverse_select` (те же параметры, что у `alt_select`), `on_player_reverse_selected_area` заведён на тот же обработчик, что и `on_player_alt_selected_area`.
   - Отдельно (не баг, документированное ограничение фазы, но подана как жалоба): **несколько одинаковых сущностей можно было разместить в одной клетке.** Полноценной collision-детекции по плану нет (`phase-2-plan.md`, «Область фазы»). Добавлена точечная защита — повторный клик в уже занятую клетку (по `find_entity_at`) не размещает вторую сущность, а сообщает игроку. Не полноценная проверка пересечения footprint'ов (см. известные ограничения).
4. **Второй раунд playtest'а: `[`/`]` не реагировали вообще (ни в чате, ни в логе).** Найдено сверкой с реальными файлами установленной игры (`doc-html/prototype-api.json`) — `bracketleft`/`bracketright` не входят в список валидных имён `key_sequence`. Правильные — `LEFTBRACKET`/`RIGHTBRACKET`. Исправлено, заодно перепроверены остальные имена клавиш в том же файле (все корректны).
5. **Verification по логу (`factorio-current.log`, прочитан напрямую, без пересказа пользователем) подтвердил DoD-тест фазы полностью** — см. «Playtest-чеклист» ниже.
6. **Второй раунд `/code-review` на полном диффе ветки (после playtest-фиксов) нашёл 6 новых находок**, все закрыты одним заходом без нового SDD fix-loop (маленькие, независимые правки):
   - `teleport_out`'s восстановление запиненного blueprint'а исходило из допущения "курсор пуст перед `swap_stack`" (верно для Phase 1), которое сломал безусловный `eb-cursor-tool` в edit-режиме (Задача 5 этой же фазы) — курсор чистится явно перед `swap_stack`. Вероятно, было безобидно на практике (`only-in-cursor`-флаг `eb-cursor-tool`, скорее всего, не даёт Factorio его "уронить" на землю) — playtest этого не поймал, но полагаться на этот побочный эффект engine'а не стоит.
   - Комментарий про occupied-guard уточнён — защита сравнивает только точку клика с footprint'ом уже стоящей сущности, не footprint размещаемой; отличающиеся по размеру сущности всё ещё могут наложиться. Задокументировано, не расширяет scope этой фазы.
   - `find_entity_at` не переставляет `tile_width`/`tile_height` для повёрнутой на 90°/270° несимметричной сущности — тот же вывод, что и в финальном ревью (см. известные ограничения, не исправлено намеренно).
   - Дублирование "найти сессию → найти сущность → выйти, если не найдена" в 4 обработчиках `input.lua` — вынесено в `get_session_and_entity()`.
   - `on_cursor_stack_changed` молчал при неудачном `clear_cursor()`, в отличие от аналогичного случая в `surface.lua` — добавлено то же сообщение игроку.
   - Один англоязычный комментарий в `spec/canvas_spec.lua` (нарушение правила "все артефакты на русском") — переведён.

## Известные ограничения / перенесено в следующую фазу

- **Move/перемещение существующей сущности не реализовано** — осознанное сужение scope, роадмап Phase 2 называет только add/remove/rotate. Workaround: remove + place заново.
- **Полноценной collision-детекции нет.** Точечная защита от повторного клика в ту же клетку добавлена по итогам playtest'а, но не проверяет пересечение footprint'ов разных по размеру сущностей — разместить сущность, частично перекрывающую соседнюю, всё ещё можно.
- **Поворот несимметричной ИМПОРТИРОВАННОЙ сущности не пересчитывает позицию/hit-box под новую ориентацию.** `snap_position`/`find_entity_at` используют статичные `tile_width`/`tile_height` прототипа без поправки на текущий `direction`. Ни одна из 7 сущностей ad-hoc палитры не несимметрична, так что свежеразмещённые сущности не задеты — только импортированная несимметричная сущность (например, котёл 3×2), повёрнутая через `R`. Тихий дрейф позиции, не крах; всплывёт на экспорте (Phase 4), если не будет исправлено раньше. Найдено дважды независимо (финальный ревью и повторный `/code-review`) — оставлено намеренно, требует дополнительного исследования API (переставляет ли Factorio эффективные размеры при вращении, что не проверялось в этой сессии), не механический фикс.
- **`selected_palette_item`, подобранный через `Q` у сущности не из палитры, десинхронизирует цикл `[`/`]`.** Первое нажатие `[`/`]` после такого подбора прыгает на `PALETTE_ITEMS[1]`, теряя подобранный тип. Мелкая UX-шероховатость, не блокер.
- **Никакого живого индикатора выбранного типа палитры на курсоре нет** — только сообщение в чате при подборе/цикле. Полноценная палитра с иконками — Phase 5.
- **`quality` не используется** — размещаемые сущности всегда `"normal"`. Явно привязано к Phase 5 (каталог) по ADR-0001 §7.
- **Ad-hoc `PALETTE_ITEMS`** (7 жёстко зашитых имён в `input.lua`) — единственное сознательное отступление от принципа «generic-каталог без хардкода имён» в этой фазе, полностью заменяется `catalog.lua` в Phase 5.
