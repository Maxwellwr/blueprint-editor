# Phase 3 — Tiles — реализация

- Ветка: `phase-3-tiles` → `main`
- Версия после мержа: `info.json` `0.4.0`
- Дата завершения: 2026-09-07

## Что сделано

- `scripts/migrations.lua` — шаг `0.4.0`: нормализация `Session.selected_palette_item` из голой строки (Phase 2) в `{kind = "entity"|"tile", name = ...}` для сессий, переживших обновление мода в момент нахождения игрока в редакторе.
- `scripts/canvas.lua` — мутационное API тайлов: `place_tile` (всегда перезаписывает клетку, без occupied-guard — семантика «покраски»), `remove_tile`, `find_tile_at` (прямое попадание по ключу клетки, без footprint-перебора — тайлы всегда 1×1), плюс чистая логика с TDD-покрытием: `tile_coordinates` (`floor` по обеим осям — не odd/even-центрирование, как у `snap_position`), `tile_key` (тот же формат `"x,y"`, что уже использует `blueprint_io.build_import_data`). По итогам финального ревью добавлен приватный (не экспортируемый) хелпер `tile_key_at(session, world_position)`, убирающий дублирование последовательности `to_local_position → tile_coordinates → tile_key` между `place_tile`/`find_tile_at`.
- `scripts/rendering.lua` — `draw_tile`/`clear_tile_render` (поштучные аналоги Phase 2, `draw_tiles` рефакторен в цикл по ним); `draw_tile` первой строкой чистит предыдущий render-объект под тем же ключом — обязательно для перезаписи, иначе повторная покраска клетки копит висячие `LuaRenderObject`. Добавлен `TILE_RENDER_WARN_THRESHOLD` (закрывает пробел, унаследованный от Phase 1, где у `draw_tiles` не было явного порога, в отличие от `ENTITY_RENDER_WARN_THRESHOLD`).
- `scripts/input.lua` — `PALETTE_ITEMS` объединён в один список `{kind, name}`: 7 сущностей (без изменений) + 4 тайла (`concrete`, `stone-path`, `refined-concrete`, `landfill`). `[`/`]` листают весь список без отдельного режима entity/tile. Общий хелпер `get_session_and_target` определяет приоритет «сущность, потом тайл» для удаления (`remove_at`, используется alt-select и `eb-delete`) и подбора (`eb-pick-entity`) — `eb-rotate` остаётся entity-only через отдельный `get_session_and_entity` (у тайлов нет direction). Новых custom-input'ов не добавлено — весь функционал лёг на существующие с Phase 2 хоткеи.
- `locale/en/controls.cfg` — подписи `eb-delete`/`eb-pick-entity` уточнены («entity/tile»).
- `spec/canvas_spec.lua` — новые тесты `tile_coordinates`/`tile_key`, плюс (по итогам финального ревью) тест, реально вызывающий `blueprint_io.build_import_data` и сверяющий его ключ с `canvas.tile_key` — контракт совместимости ключей `session.tiles` между двумя независимыми модулями теперь проверяется тестом, а не только комментарием.
- `.luarc.json` — `prototypes` добавлен в список известных Factorio-глобалов для Lua language server (снимает ложное предупреждение IDE, накопившееся с Phase 2).
- `busted`: 31/31 тестов (было 30 после Phase 2; +1 tile_coordinates/tile_key edge cases сверх первоначального плана — контрактный тест с `blueprint_io`).

## Найденные API-факты (проверены на установленной `2.0.77`, `docs/sdlc.md` «Версия Factorio и проверка API-фактов»)

1. **`Tile`/`TilePosition` (концепт blueprint-тайла) — `{name, position}`, координаты целочисленные, получаемые округлением **вниз** (`floor`).** Подтверждено `doc-html/runtime-api.json`: «rounds any non-integer x/y down to whole numbers» — принципиально другое правило, чем у сущностей (`snap_position`, odd/even-центрирование по `tile_width`/`tile_height`). У тайлов нет аналога `tile_width`/`tile_height` — они всегда 1×1, без ориентации/`direction`/`quality`.
2. **Имена тайловых прототипов ad-hoc-списка проверены в файлах установленной игры** (`data/base/prototypes/tile/tiles.lua`), не по памяти: `concrete`, `stone-path`, `refined-concrete`, `landfill`.
3. **`LuaRendering.draw_sprite`'s `render_layer` по умолчанию — `"arrow"` (RenderLayer 190), если не задан явно.** Это найдено не при планировании, а по факту playtest-бага (см. «Решения, принятые по ходу», пункт 2): `M.draw_entity` и исходная версия `M.draw_tile` обе полагались на этот дефолт и попадали на один и тот же слой. `RenderLayer`'s правило — «higher values are rendered above lower values» — **абсолютное**, а не поведение только при точном равенстве значений (то есть не нужно гадать про tie-break при столкновении: любое строго меньшее значение гарантированно рисуется ниже). Подтверждено `doc-html/runtime-api.json` установленной `2.0.77`.

## Решения, принятые по ходу (отклонения/дополнения к phase-3-plan.md)

Порядок отражает реальную последовательность: SDD-исполнение по задачам плана (1-4, без отклонений от него) → добавление временного playtest-логирования → ручной playtest пользователем → найден и исправлен рендер-баг → повторная проверка пользователем (подтверждена по логу) → финальный whole-branch review → одна фикс-волна по его находкам → scoped re-review (чисто).

1. **Задачи 1-4 плана выполнены практически дословно** — план для этой фазы включал точный код каждой задачи, и все четыре implementer-субагента транскрибировали его без отклонений (подтверждено пословным сравнением на task-review каждой задачи). Единственное решение по ходу внутри самих задач — Задача 2 не расширялась (использован ровно тот же трёхшаговый паттерн `to_local_position`/`tile_coordinates`/`tile_key` в `place_tile` и `find_tile_at`, что и было прописано в плане; дедупликация вынесена уже позже, на финальном ревью).
2. **Playtest нашёл рендер-баг вне TDD/task-review: сущности поверх тайла после импорта визуально пропадали, хотя данные оставались целы** (occupied-guard при повторном клике на то же место срабатывал; `/eb-dump-session` подтвердил все сущности на месте с корректными позициями/проводами). Причина — `M.draw_entity` (не тронут этой фазой) и `M.draw_tile` (эта фаза, скопировала поведение Phase 1 без изменений в этой части) обе не задают `render_layer` и попадают на один дефолтный слой `"arrow"`; поскольку `control.lua` рисует сущности, а затем тайлы, тайл на общей клетке визуально перекрывает сущность. Это латентный баг, унаследованный от Phase 1 (там `draw_tiles`'s тело рисования спрайта не менялось этой фазой вплоть до самого фикса) — впервые стал наблюдаем только сейчас, потому что только в Phase 3 впервые явно тестируется сочетание «сущность на тайле». Исправлено явным `render_layer = "ground-layer-1"` у тайлов (сущности не тронуты — их дефолт `"arrow"` уже безусловно выше). Верифицировано пользователем повторно после фикса; независимо подтверждено по `factorio-current.log` (перезагрузка карты после фикса, серия `pick`/`place_tile` в том же регионе, где раньше были «невидимые» сущности, — ни одной ошибки/`no sprite`-фоллбэка).
3. **Финальный whole-branch review (Opus, до playtest-фиксов не проводился отдельно — фаза меньше Phase 2, ревью запущено один раз на всю ветку сразу после плейтеста и его фикса) дал 0 Critical, 4 Important, 9 Minor.** Все Important и часть Minor закрыты одной фикс-волной (без отдельного фиксера на каждую находку), scoped re-review подтвердил все 7 применённых фиксов адресованными без новых поломок:
   - Контракт «`canvas.tile_key` даёт тот же ключ, что `blueprint_io.build_import_data`» держался только на комментарии, не на тесте — добавлен тест, реально вызывающий обе функции и сверяющий результат.
   - Комментарий у `render_layer = "ground-layer-1"` расширен до полноценной записи найденного API-факта (см. выше, пункт 3) — включая точные числовые значения слоёв и источник (`doc-html/runtime-api.json`), чтобы не повторить историю Phase 1 с `LuaRecord.label` (забытый API-факт, стоивший рабочего краша).
   - `cycle_palette` записывал в `storage` прямую ссылку на элемент модульной константы `PALETTE_ITEMS` вместо копии (`on_pick_entity` уже строил свежую таблицу) — выровнено на копирование.
   - Дублирование `to_local_position`→`tile_coordinates`→`tile_key` в `place_tile`/`find_tile_at` — вынесено в приватный `tile_key_at`.
   - `remove_at` в `input.lua` неявно трактовал «не сущность» как «тайл» — заменено на явный `elseif kind == "tile"` + `error()` на непредвиденном значении (fail-fast, `docs/sdlc.md`).
   - `TILE_RENDER_WARN_THRESHOLD = 4000` оказался ниже размера рутинного крупного blueprint'а (площадка 64×64 — уже 4096 тайлов) — поднят до `10000`.
   - Незакоммиченная правка `.luarc.json` (глобал `prototypes`, оставшаяся с Задачи 4) закоммичена отдельным `chore:`.
4. **Не исправлялось намеренно, запарковано с обоснованием** (не блокирует DoD):
   - `draw_tile` не проверяет `session.tiles[key]` на `nil` перед чтением `record.raw` — тот же контракт «ключ обязан существовать до вызова», что и у `draw_entity` с Phase 2, не новая непоследовательность.
   - `canvas_surface()` вызывается на каждый тайл внутри `draw_tiles` (не поднят из цикла) — так же устроен `draw_entities`, оставлено ради консистентности между двумя параллельными функциями, стоимость незначительна.
   - Drag-select (протаскивание с зажатой кнопкой) красит только центральную клетку выделенной области (`area_center` сводит любую область к точке) — тот же паттерн, что и у сущностей в Phase 2, не отклонение от плана (сценарий фазы описывает именно «клик»), но первый жест, который применит будущий каталог-режим Phase 5 к тайлам, — задокументировано как известное ограничение ниже.
   - Обоснование Задачи 1 в `phase-3-plan.md` неточно описывает механизм отказа без миграции (говорит про «упадёт с ошибкой», реально было бы тихое `nil`-попадание в тайловую ветку с падением уже на `prototypes.tile[nil]`) — вывод (миграция нужна) не меняется, сам план не переписывался задним числом, зафиксировано здесь для будущего читателя.

## Известные ограничения / перенесено в следующую фазу

- **Вращение тайлов не реализовано и не может быть реализовано в этой модели данных** — у `Tile`/`TilePosition` в принципе нет направления/ориентации (найденный API-факт, не отложенный нюанс).
- **Drag-select красит только центральную клетку выделенной области**, не всю протащенную полосу — `area_center` сводит любую область к точке, тот же паттерн, что у сущностей в Phase 2. Первый жест, который реально захочет попробовать игрок с тайлами («провести кистью»), но план фазы обещал только «клик», не drag-заливку. Кандидат на доработку, если станет заметным трением в реальном использовании — не тривиальное расширение (потребует итерации по всем клеткам `event.area`, отдельного дизайн-решения по производительности при больших областях).
- **`TILE_RENDER_WARN_THRESHOLD = 10000`** (и `ENTITY_RENDER_WARN_THRESHOLD = 2000` из Phase 1/2) — обе по-прежнему грубые оценки, не откалиброванные по факту реальной нагрузки; уточнение — Phase 7 (явный бюджет производительности для render-объектов, ADR-0001/`docs/sdlc.md`).
- **Ad-hoc `PALETTE_ITEMS`** (7 сущностей + 4 тайла, жёстко зашитые в `input.lua`) — как и в Phase 2, единственное сознательное отступление от принципа «generic-каталог без хардкода имён», полностью заменяется `catalog.lua` в Phase 5.
- **Ранее найденное в Phase 2 ограничение (поворот несимметричной импортированной сущности не пересчитывает hit-box) не изменилось и не связано с тайлами** — по-прежнему актуально, перенесено без изменений.
- **`export_to_entities_array`/сохранение обратно в blueprint** — Phase 4, без изменений; `session.tiles` уже в форме, готовой для будущего экспорта.
